# 本地阅读助手：使用与记忆机制

这是运行在本机的个人阅读工具，不是商业化产品。默认使用本地模型，也可显式启用外部模型 API。功能测试不代表科研性能或学习效果。

## 启动

先按 [README](../README_CN.md) 安装 Python 环境和依赖。Windows 可在仓库根目录只启动页面：

```powershell
.\scripts\start_local.ps1 -ApiOnly
```

仓库不含模型权重或运行器。脚本使用独立 `.venv-reading`；若尚未按 README 创建环境，自动创建需 `uv`。界面在 `http://127.0.0.1:8502`。llama.cpp 模式的模型接口在 `127.0.0.1:8384`，两者都只监听本机。模型启动后需等待加载；页面可以提前打开。

llama.cpp 模式需显式传入 `-LlamaServer '路径\llama-server.exe' -ModelPath '路径\model.gguf'`，可选 `-Python '路径\python.exe'`；运行器/模型路径也可通过 `MEMORYRUSH_LLAMA_SERVER` 与 `MEMORYRUSH_MODEL_PATH` 指定。或先自行启动 Ollama、安装本地模型，再运行 `start_local.ps1 -Ollama`，在“设置”选择 Ollama 并填实际模型名。本地模式只连接回环地址，但不能替用户保证一个任意本机服务内部的行为；要保持纯本地，请不要选择 Ollama 云模型。

只使用 API、不启动本地模型时运行 `./scripts/start_local.ps1 -ApiOnly`。首次进入可先看到离线预览，在设置中启用 API 后才发送请求；已有保存的模型选择会继续沿用。此开关不停止任何已运行的本地服务。

关闭运行脚本的终端会停止页面。后台模型可能继续驻留；再次启动会复用占用 8384 的服务，不会杀掉其他进程。模型不作为系统服务安装；重启电脑后重新运行脚本即可。

## 日常用法

打开即是类似 Codex 的对话入口：轻量左侧历史会话、收窄的消息流、右对齐的用户气泡。新对话在中央输入；有消息后输入框固定在底部。顶部模型按钮可以直接打开模型设置。

1. 直接提问，自动召回已读文章的记忆。左侧“新对话”创建草稿，发送第一条消息后才保存；切换历史会话可以继续追问，最近最多 3 轮参与理解上下文。
2. 用输入框的 **＋** 附加 UTF-8 TXT / Markdown，可以同时写一个问题；发送后依次提取、模型评分、存储，再回答附带问题。附件与结果保存在这一轮对话中。仅阅读不会强化记忆，实际引用仍按原规则强化。
3. 也可以选择左侧“粘贴文章”，粘贴正文并标记重点段落。长文按小段请求依次处理；分段摘要不是另做的全文综合摘要。附带问题限 1500 字，正文请放在附件或文章正文中。
4. 每条回答下的“记忆轨迹”显示检查、召回、实际引用的数量，展开可核对原文。顶部“记忆面板”按需打开右侧检查区；“召回范围”可限定某篇文章或全部文章。
5. 在“记忆库”检查每项分数理由、原文、当前强度、半衰期与使用记录，可启用、待审、停用或固定。证据无效和离线预览的候选不能手动启用。已读文章可从左侧或消息中的“查看阅读记录”打开。
6. 模型接口、名称、地址、阅读兴趣与每篇保留数量收进左侧“设置”，保存后下次仍生效。兴趣只参与新记忆评分，不会偷偷重写旧分数。

文章保存后，如果附带问题回答失败，仍保留阅读结果并明确显示错误，可以继续提问而不用重新上传。离线预览只演示界面与处理流程，不会冒充 LLM 打分或启用自动召回。新界面使用 Streamlit 1.64 或更新的 1.x 版本。

“停用”是可恢复的软停用，不是擦除原文或历史聊天。再次导入同一篇内容不会重复创建同一条记忆，也不会取消用户的停用决定。重新导入的处理记录仍可查看；相同记忆保留首次存储的评分与状态，不自动覆盖。若模型重述为另一条内容，仍可能形成新候选，召回时另做近重复抑制。

## 使用其他模型 API

在顶部模型按钮或左下“设置”中选择 **外部 API**，填写服务、模型 ID、Base URL（基础地址）或完整 `/chat/completions` 地址、API Key。预置 OpenAI、DeepSeek、阿里云百炼/Qwen 地址，也可以填自定义 OpenAI 兼容服务；模型 ID 由你填写，不假定某个最新型号可用。百炼地址/密钥须匹配地域，支持修改为你的业务空间专属域名。

保存前需勾选发送范围和费用确认；仅打开设置、填写或保存配置不会调用 API。缺少密钥时输入框禁用，但历史与记忆仍可查看。默认本地模型失败后不会自动切换云端。

- 提取会发送文章正文；评分还会使用阅读兴趣、标注及参与比较的旧记忆。
- 对话相关性判断会分批发送所选范围内的**所有启用记忆**，不是只有最后选中的五条；回答阶段发送问题、最近最多三轮对话、选中记忆与原文引文。一轮操作可能含多次付费请求。
- 密钥只放在当前浏览器会话的服务端内存中，并绑定到完整目标地址；不写入 SQLite、项目配置、处理记录或导出文件。重新打开浏览器/重启应用可能需要重填；也可自行设置专用环境变量，并在设置中填写变量名。环境变量值同样不复制到数据库。不要在对话或 URL 里写密钥。
- 地址只接受 HTTPS；保留系统证书校验，禁止重定向与隐式 HTTP 代理。HTTP 错误只显示状态与操作建议，不展示可能含密钥/私人文本的原始错误体。失败不自动重试，不静默降级接口或绕过评分与证据检查。
- 应用数据仍在本机，但调用 API 的内容会离开本机；服务商保留与处理政策由其决定。清除会话密钥不会删除你自行设置的环境变量。

“兼容性与密钥选项”可选 `json_object`、`json_schema` 或仅提示词要求 JSON 的 `prompt` 模式。Schema 模式在有结构定义的评分/召回请求使用严格结构；提取和回答仍按 JSON 对象处理，程序端始终验证数值、引用等。OpenAI 预置 `max_completion_tokens`；其他兼容服务默认 `max_tokens`，可按服务商要求切换。每次输出额度默认 8192 tokens（含模型内部推理），可调整；不强制发送模型可能不支持的温度参数。

这是 **Chat Completions 兼容接口**，不是对所有厂商原生协议的承诺；目前没有 Anthropic 原生 Messages、Responses-only 模型、图像输入或逐 token 流式输出。接口拒绝、截断、无效 JSON/引用会明确失败。当前外部适配已经通过模拟 HTTP 与整条评分/召回流程测试，未用真实付费密钥做第三方端到端验收。

接口依据：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[DeepSeek 兼容接口](https://api-docs.deepseek.com/)、[阿里云百炼兼容说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)。这些文档描述各自接口，不保证任意模型都支持相同结构选项。

## 让模型真正打分

提取、评分和对话均使用设置中当前选择的模型；切换接口不会自动重写已保存的评分。

提取与评分是两次独立调用。评分使用版本化量表、JSON Schema（结构约束）、数值范围校验，以及每个维度的简短理由。缺失条目、缺失理由、重复索引、非有限数、字符串分数和超范围分数都拒绝；不偷偷裁剪或用启发式分数冒充 LLM。

| 维度 | 权重 | 依据 |
| --- | ---: | --- |
| 重要性 | 0.18 | 是否是核心概念、机制、结论 |
| 相对新颖性 | 0.12 | 是否区别于本次提供的旧记忆 |
| 个人相关性 | 0.18 | 是否服务于显式阅读兴趣 |
| 未来用途 | 0.14 | 是否能用于学习、解释或决策 |
| 启发性 | 0.10 | 是否提供有证据的反直觉区分 |
| 旧记忆关联 | 0.12 | 与已提供旧记忆的具体联系 |
| 证据支持 | 0.06 | 引文是否支持整条陈述 |
| 用户标注 | 0.10 | 是否关联你显式标注的原文段落（程序计算） |

每项范围 0–1；基础分是上述加权和。另让模型评估 `durability`（持久性）以选择半衰期。没有兴趣资料时个人相关性为 0.5；没有旧记忆时新颖性为 0.5、关联为 0，并保留模型原分与上下文默认覆盖记录。

新颖性不是世界范围的创新性判断：每批只提供最多 5 条词面最接近的旧记忆。评分可有偏差，需要查看理由与原文。逐字证据检查独立于模型评分：高分不能绕过段落和引文检查。基础分至少 0.35、模型证据支持至少 0.6，才可自动进入数量预算；另施加近重复惩罚。待审的有效候选可由用户显式启用。

## Decay：衰减与强化

```text
当前强度 = 事件时强度 × 2 ^ (-间隔天数 / 半衰期天数)
初始事件时强度 = 基础分
```

类型基准半衰期：概念/机制 60 天、一般主张 30 天、事实 21 天、例子 14 天、临时内容 3 天；乘以 `(0.5 + 模型持久性)`。未知类型使用 30 天。时间戳统一为 UTC，读取时计算，不需要后台定时器。页面刷新不会叠加衰减，时间回拨不会产生大于原值的增益。

模型回答中实际引用的记忆，且 ID、引文匹配检查通过后，才写入 `used_in_answer` 事件。只被评相关性或送入候选上下文不强化。证据不足的回答不强化。

有效强化时：`新强度 = 当前强度 + 0.18 × (1 - 当前强度)`；半衰期延长 15%，上限 365 天。同一条记忆 24 小时最多自动强化一次，其他使用事件仍记录。同一对话轮重放不重复计数；回答与事件同一数据库事务写入。强化奖励本身也衰减，不形成永久不忘的累计常数。固定记忆冻结当前强度；解除固定从当时继续计时，不倒算冻结期间的衰减。

这些是可检查、可调整的软件默认值，不是已经证明的人类遗忘曲线，也没有经过学习效果校准。

## 自动 Recall：后续对话如何用记忆

模型逐批评估所有已启用记忆对当前问题的相关性（包含不相关项）；不会只按关键词截断候选。相关性低于 0.5 的点先排除，包括固定记忆。剩余排序为 `0.75 × 相关性 + 0.25 × 当前强度`，再抑制重复，最多送入 5 条，受模型上下文容量约束。

回答生成只获得选中记忆及其原文引文。历史对话只用于理解追问，不是新增证据。答案逐段列出引用的 Memory Point ID 和原文摘句；未知 ID、伪造引文、截断响应会导致本轮失败，不存为成功回答。未找到相关记忆时明确说证据不足。

这能机械验证“引用确实存在”，但不能保证生成句句正确或语义必然被证据支持；请核对重要内容。当前按批扫描全部记忆适合个人小型库，数量增加时推理耗时会增长；尚未增加向量索引。没有 PDF/OCR、网页抓取、多用户或云端同步。

## 数据与命令行

Windows 默认：`%LOCALAPPDATA%\MemoryRush\memory.sqlite3`，避开 OneDrive 中的源代码目录。可用 `MEMORYRUSH_DATA_DIR` 改位置；若改到同步目录，数据可能被同步软件上传。数据库未加密。备份时关闭页面后复制数据库及同目录的 `-wal`、`-shm` 文件；不要只复制正在使用的主数据库。处理导出、测试回执可能含完整阅读内容，不要公开。

```powershell
.\.venv-reading\Scripts\python.exe -m memoryrush.cli process data/sample_docs/reading_memory_example.txt
.\.venv-reading\Scripts\python.exe -m memoryrush.cli memories
.\.venv-reading\Scripts\python.exe -m memoryrush.cli ask "之前读过的内容里，哪些解释了记忆衰减？"
# 使用输出的 Session ID 继续追问
.\.venv-reading\Scripts\python.exe -m memoryrush.cli ask "它为什么有用？" --session <Session-ID>
```

本地适配器基于 [Ollama 生成接口](https://docs.ollama.com/api/generate) 与 [llama.cpp 本地服务接口](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。本地适配器仍禁止外部地址；只有显式启用的 API 适配器可发送远程请求。界面不用远程字体，模型输出以纯文本展示。

命令行也支持 API：先自行设置专用密钥环境变量，然后运行（不要把密钥本身作为命令参数）：

```powershell
.\.venv-reading\Scripts\python.exe -m memoryrush.cli ask "这篇文章有什么启发？" --provider api --endpoint https://your-provider.example/v1 --model your-model-id --api-key-env MEMORYRUSH_API_KEY --allow-remote
```

`process` 同样支持这些参数。`--allow-remote` 是显式发送许可，缺省不会请求；`--json-mode`、`--token-parameter`、`--api-output-tokens` 与界面选项相同。示例地址和模型名是占位符，须换成你的实际配置。

## 验证与边界

运行阅读助手的离线测试：

```powershell
python -m pytest -q
# 可选：另行准备真实 llama.cpp 服务后运行，不属于离线测试
python scripts/smoke_local.py
```

真实本地检查使用合成示例，在私人数据目录的 `verification/` 中独立建库、保留调用与回执；不修改主记忆库、不表示科研性能。失败保留，不自动反复重试。

公开仓库不包含个人数据库、验证原始轨迹或内部研究工作区。
